# PennyWise Infrastructure (Terraform)

Terraform configuration for the PennyWise 10M-user platform on AWS.

## Stack

| Component | Resource | Notes |
|---|---|---|
| Networking | VPC + 3 AZs, NAT, public/private subnets | `terraform-aws-modules/vpc` |
| Compute | EKS cluster + managed node group | Runs all Go microservices (HPA per service) |
| Events | Amazon MSK (Kafka 3.7, TLS) | Event bus: ledger, marketdata, notifications |
| Cache | ElastiCache Redis 7 (encrypted) | Sessions, quote cache, rate limiting |
| Database | CockroachDB Cloud dedicated (3 nodes) | Distributed SQL, partitioned tables |

## Layout

```
infra/terraform/
├── main.tf          # root stack wiring all modules
├── variables.tf     # shared variables
├── outputs.tf       # connection endpoints
└── modules/
    ├── eks/         # EKS cluster + node group + IAM
    ├── msk/         # MSK cluster + security group
    ├── redis/       # ElastiCache Redis replication group
    └── cockroachdb/ # CockroachDB Cloud dedicated cluster + SQL user
```

## Prerequisites

- Terraform >= 1.5
- AWS credentials (profile or env vars)
- CockroachDB Cloud API key

## Usage

```sh
terraform init
export TF_VAR_cockroachdb_api_key=...
terraform plan -var-file=environments/production.tfvars
terraform apply -var-file=environments/production.tfvars
```

The S3 backend (`pennywise-terraform-state`) and DynamoDB lock table must
exist before the first `terraform init` (see `bootstrap/` for a script).

## Security notes

- All service-to-service traffic is TLS; MSK client-broker is TLS-only.
- Redis has at-rest and in-transit encryption enabled.
- CockroachDB allow-list is open (`0.0.0.0/0`) for P0; replace with EKS
  node security-group CIDRs before production traffic.
- Secrets (DB password) are generated by Terraform; wire them into EKS
  secrets via AWS Secrets Manager in the deployment phase.
